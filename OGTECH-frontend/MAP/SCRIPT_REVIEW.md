# 팀원 지도 스크립트 검토 결과

검토 대상: `jetson_navigation_demo`

## 결론

고정 좌표의 A* 경로 계산은 정상이다. 하지만 패키지는 원본 오프라인 지도를 변환하지 않으며, 현재 상태 그대로 현장 항법 입력을 받기에는 안전 검증이 부족하다. 이 폴더의 검증 앱은 원본을 수정하지 않고 누락된 검증 경계를 별도 구현한다.

## 확인된 정상 동작

- 샘플 그래프는 노드 933개, 방향 엣지 2,668개이며 모든 노드에 `x/y`, 모든 엣지에 양의 `length`가 있다 `[실측]`.
- 고정 시작점에서 목적지까지 913.08m, 26개 노드가 계산됐다 `[실측]`.
- 고정 시드로 뽑은 좌표 쌍 200개 중 경로가 존재한 191쌍에서 A*와 Dijkstra 결과가 모두 일치했다 `[실측]`.
- Python 구문 컴파일과 GeoJSON 좌표 순서 `(longitude, latitude)`가 정상이다 `[실측]`.

## 보완이 필요한 문제

### 1. 지도 변환 단계가 없다

`run_demo.py`는 이미 만들어진 `konkuk_walk.graphml`만 읽는다. README에도 원본 `.osm`과 변환 의존성은 포함하지 않았다고 적혀 있다. 따라서 "오프라인 지도 → GraphML" 재현성은 이 패키지만으로 검증할 수 없다.

검증 앱은 GraphML을 권장 입력으로 받고, 비교용 OSM XML 부분 변환기를 함께 제공한다. 생산용 OSM 변환은 팀의 OSMnx 명령·영역·필터·버전을 별도 스크립트로 고정해야 한다.

### 2. 지도 밖 좌표를 조용히 스냅한다

기존 `_nearest_node()`에는 최대 거리가 없다. 서울 지도에 부산 좌표를 넣어도 가장 가까운 서울 노드를 현재 위치처럼 선택한다. GPS 미수신이나 잘못된 좌표를 정상 경로처럼 보일 수 있어 현장 사용에는 부적합하다.

검증 앱은 기본 250m `[추정: 검증용 상한]`를 넘으면 경로를 거부하고 실제 스냅 거리를 표시한다.

### 3. 곡선 도로 형상이 경로 출력에서 사라진다

샘플 GraphML의 엣지 884개에 WKT `geometry`가 있지만 `[실측]`, 기존 `to_geojson()`은 경로 노드만 직선으로 연결한다. 계산 거리 자체는 엣지 `length`를 쓰므로 맞아도 화면 선이 건물이나 장애물을 가로질러 보일 수 있다.

검증 앱은 선택된 엣지의 `LINESTRING`을 방향에 맞춰 이어 붙인다.

### 4. 입력 계약 검증과 회귀 테스트가 없다

기존 로더는 `x/y` 또는 `length` 누락·NaN·음수, WGS84가 아닌 CRS, 끊긴 그래프를 명시적으로 검사하지 않는다. 샘플 그래프에는 약한·강한 연결 컴포넌트가 각각 4개 있어 `[실측]` 컴포넌트 간 `RouteNotFound`가 발생할 수 있지만 시작 시 경고하지 않는다.

검증 앱은 이 조건들을 업로드 시 검사하고 자동 테스트로 고정했다.

### 5. 의존성 범위가 넓다

`networkx>=2.8,<4`는 설치 시점과 Python 버전에 따라 다른 버전을 선택한다. JetPack 5.1.x의 기본 Python 3.8을 대상으로 검증 앱은 NetworkX 3.1로 고정했다 `[출처: requirements.txt]`.

## 안전 계약 확인

- 경로·거리·스냅은 전부 `map_engine.py`가 계산한다.
- LLM에는 지도 그래프나 전체 경로를 넣지 않고, 화면에 보이는 작은 `DEVICE_STATE`만 읽기 전용 후보로 만든다.
- 샘플과 수동 입력은 실제 GPS가 아니므로 `모의 데이터` 태그를 항상 표시한다.
- 실제 GPS 미수신을 추정 위치로 바꾸는 코드는 넣지 않았다.

## 검증 앱 대형 지도 수정

광진구 GraphML로 앱 자체를 다시 검사하면서 다음 병목을 확인하고 수정했다.

- GraphML 엣지마다 `number_of_edges()`를 호출하는 기본값 표현식이 엣지 ID가 있어도 실행됐다. 엣지 122,126개에서 제곱 시간으로 느려져 활성 지도 교체에 도달하지 못했다 `[실측]`.
- 엣지 키 폴백을 O(1) 카운터로 바꾼 뒤 광진구 그래프 적재·검증은 개발 PC에서 6.47초로 줄었다 `[실측]`.
- 연결 컴포넌트 집합을 한 번만 계산해 기본 지점 선택에 재사용한다.
- 런타임 JSON은 전체 딕셔너리와 문자열을 동시에 만들지 않고 스트리밍 저장한다. 광진구 런타임 파일은 9.7MB이며 저장은 1.72초였다 `[실측]`.
- 화면 도로는 파일 앞부분 12,000개가 아니라 지도 전체 격자에서 공간 균등 표본으로 선택한다. 광진구 지도에서는 8,883개가 선택됐다 `[실측]`.
- 실제 웹 API 업로드는 개발 PC에서 13.11초, 앱 재시작은 3.10초, 기본 경로 계산은 0.75초에 완료됐다 `[실측]`. Jetson 수치는 아직 측정하지 않았다 `[미검증]`.
