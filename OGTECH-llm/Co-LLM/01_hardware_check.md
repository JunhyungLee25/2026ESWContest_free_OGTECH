## 2. 이게 왜 좋은 소식인가

`docs/00_frozen_decisions.md` §1 고정 하드웨어 표는 **INMP441(I2S 마이크) + MAX98357A(I2S 앰프)**입니다.
I2S를 Xavier NX 40핀 헤더에 붙이려면 디바이스 트리 오버레이(`simple-audio-card` 노드)를
직접 작성하고 `jetson-io`로 적용한 뒤 재부팅해야 합니다. 반나절짜리 작업이고,
**틀리면 오디오가 안 나는 게 아니라 커널이 카드를 아예 안 만듭니다.** 원인 분리가 어렵습니다.

지금 확인하려는 것은 I2S 배선이 아니라 **STT → LLM → TTS 소프트웨어 배관**입니다.
USB 오디오 장치 2개면 `lsusb`에 뜨는 즉시 ALSA 카드가 생기므로,
**배관 문제와 배선 문제를 분리해서 볼 수 있습니다.** 이 순서가 맞습니다.

---

## 3. 이게 최종 부품은 아닙니다

USB를 최종안으로 가져갈 때의 문제를 미리 적어 둡니다. 나중에 다시 논의하지 않기 위해서입니다.

| 항목 | USB 오디오 | I2S (INMP441 / MAX98357A) |
|---|---|---|
| 외함 관통 | USB 커넥터 2개 → **IP67 방수 부담** | 케이블 직결, 관통부 최소 |
| 전원 | 5 V 버스 상시. 허브·컨트롤러 상시 소비 | 3.3 V, 앰프는 SD 핀으로 완전 차단 가능 |
| 지연 | USB 프레임 스케줄링 오버헤드 [추정] | DMA 직결 |
| STM32 상시 계층 | **Jetson이 꺼지면 같이 죽음** | 동일 (둘 다 Jetson 종속) |
| 배선 난이도 | 없음 | 디바이스 트리 오버레이 필요 |

**결론: USB로 소프트웨어를 확정하고, I2S 전환은 `config.py`의 장치 이름 한 줄 교체로 남깁니다.**
`voice_loop.py`는 ALSA 장치 문자열만 보므로, I2S 카드가 잡히는 순간 나머지 코드는 그대로 씁니다.

## 4. 꽂기 전 전원 점검 — 이걸 안 보면 재부팅합니다

스피커가 **2 × 2 W**입니다. 최대 볼륨에서 USB 포트 하나가 감당해야 할 전류가
표준 USB 2.0 한계(500 mA)에 근접하거나 넘길 수 있습니다 [추정].

증상은 소리가 안 나는 게 아니라 이렇게 나타납니다.

- 음량을 올리면 재생이 끊기거나 `underrun` 로그가 뜬다
- 마이크 카드가 갑자기 사라진다 (`arecord -l`에서 없어짐)
- **Jetson이 재부팅된다** — 가장 위험

대책:

1. 마이크와 스피커를 **다른 USB 컨트롤러 포트**에 꽂습니다. Xavier NX 개발자 키트의
   USB 3.x 포트 4개는 내부적으로 허브를 공유합니다. `lsusb -t`로 트리를 확인하세요.
2. 처음 테스트는 **볼륨 60% 이하**에서 합니다. `alsamixer`에서 확인.
3. 증상이 재현되면 **셀프 파워 USB 허브**를 씁니다. 이건 회피가 아니라 정상 대책입니다.
4. Jetson 전원은 **배터리가 아니라 정격 어댑터**로 테스트합니다. 배터리 경로의 전압 강하가
   섞이면 원인 분리가 안 됩니다.

## 5. ALSA 장치 이름이 겹칩니다 — 이게 첫 번째 함정

Adafruit 3367과 3369는 둘 다 일반 USB 오디오 컨트롤러를 씁니다. 그래서 ALSA에서
**둘 다 `Device`라는 이름으로 잡힐 가능성이 높습니다** [추정]. 이때 커널은 뒤에 붙은 쪽에
`Device_1`을 붙입니다.

그리고 **카드 번호(`hw:1,0`)는 꽂는 순서와 부팅 타이밍에 따라 바뀝니다.**
스크립트에 `hw:1,0`을 하드코딩하면 다음 부팅에서 마이크와 스피커가 뒤바뀝니다.

그래서 `config.py`는 **이름 기반**을 씁니다.

```python
MIC_DEVICE = "plughw:CARD=Device,DEV=0"
SPK_DEVICE = "plughw:CARD=Device_1,DEV=0"
```

`arecord -L`과 `aplay -L`이 찍어 주는 이름을 그대로 넣으세요. `scripts/00_check_audio.sh`가
후보를 뽑아 줍니다.

### `hw`가 아니라 `plughw`를 쓰는 이유

STT는 **16 kHz 모노**를 원합니다. USB 마이크가 16 kHz를 하드웨어로 지원하지 않으면
`hw:`로는 `Invalid argument`가 나면서 그냥 실패합니다. `plughw:`는 ALSA가 리샘플링·채널 변환을
자동으로 끼워 넣습니다.

**초기 테스트는 무조건 `plughw`로 하세요.** 지연을 깎는 건 배관이 뚫린 다음입니다.

## 6. 통과 기준

- [ ] `lsusb`에 마이크·스피커 두 장치가 모두 보인다
- [ ] `arecord -l`에 캡처 카드, `aplay -l`에 재생 카드가 각각 보인다
- [ ] `arecord -L` / `aplay -L`에서 쓸 이름을 확정해 `config.py`에 넣었다
- [ ] 5초 녹음 → 재생 왕복이 들린다
- [ ] 재생 중 `dmesg -w`에 USB 리셋 로그가 없다
- [ ] 재생 중 Jetson이 재부팅되지 않는다

여기까지 통과하면 [`02_install_a_to_z.md`](02_install_a_to_z.md)로 갑니다.
