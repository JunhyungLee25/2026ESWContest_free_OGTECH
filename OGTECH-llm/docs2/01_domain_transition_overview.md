# 01. 도메인 전환 개요 — 의료 지원 → 오지 생존

---

## 1. 무엇이 바뀌나

| 축 | 기존 (OGTECH Kit) | 신규 (제안) |
|---|---|---|
| 주제 | 응급처치 · 구급함 | 오지 생존 · 조난 대응 |
| 사용자 | 사고 현장의 목격자 | **혼자 오지에 들어간 초보자 본인** |
| 형태 | 거치형 구급함 (2×2 서랍) | **배낭 장착형 웨어러블** |
| 핵심 동작 | "말하면 서랍이 열린다" | **"말하면 어디로 가야 하는지 답한다"** |
| 출력 | 7인치 터치 화면 | 7인치 터치 화면 + **골전도/이어 스피커 음성** |
| 통신 | SIM7670G SMS 구조 요청 | **삭제** (사용자 결정) |
| 위치 | GPS → 구조 문자용 좌표 | **GPS → 오프라인 지도 · 길찾기 · 체크포인트** |
| 시간 축 | 사고 후 5~30분 | **출발 전 ~ 14일 이상** |

**가장 큰 변화는 하드웨어가 아니라 시간 축입니다.**
구급함은 "사고 후 10분"만 책임지면 됐습니다. 생존 장치는 **출발 전 계획부터 2주 뒤까지** 책임집니다.
이건 배터리·저장소·UI·LLM 역할을 전부 다시 계산해야 한다는 뜻입니다.

## 2. 무엇이 살아남나 (버리지 말 것)

기존 자산 중 새 도메인에서도 그대로 유효한 것들입니다. **다시 만들지 마세요.**

| 자산 | 새 도메인에서의 역할 |
|---|---|
| **고정 카드 아키텍처** (`ogtech_core.py`) | 그대로. "검수된 절차 문구는 코드에, LLM은 문장만 다듬음" 원칙은 도메인과 무관하게 성립 |
| **안전 계약 (LLM 출력을 절차 문구로 쓰지 않음)** | 그대로. 오지에서는 오히려 더 중요 (§5 참조) |
| **회색 ≠ 녹색 색 규율** | 그대로. GPS 미수신을 "정상"으로 보이게 하면 사람이 죽음 |
| **DEMO 배지 규칙** | 그대로 |
| **7인치 물리 스케일 (80px = 12mm)** | 그대로. 장갑 끼고 조작하는 조건은 오지에서 더 빡셈 |
| **Qwen2.5 1.5B Q4_K_M** | 그대로 유지 판정. 근거는 [05](05_llm_harness_redesign.md) |
| **STM32H7A3ZI-Q** | **역할 변경**: 서랍 컨트롤러 → **상시 전원 관리자 + GPS 로거**. 이게 전력 문제의 유일한 해법 ([06](06_power_budget_battery.md)) |
| **llama-server 실행 옵션 세트** | 그대로 |
| **키워드 1차 분류 + LLM 보조 분류 구조** | 그대로. 라벨 집합만 교체 |

## 5. 안전 계약 — 오지 생존판

`Co-LLM/docs/00_frozen_decisions.md` §3의 10개 항목을 도메인에 맞게 다시 씁니다.
**1~4번은 새로 생겼거나 성격이 완전히 바뀐 항목입니다.**

1. **경로·방위·거리는 절대 LLM이 생성하지 않습니다.**
   방위각, 거리, "이쪽으로 가세요"는 지도 엔진(코드)이 GPS·타일 데이터로 계산합니다.
   LLM은 그 결과를 **읽어 주기만** 합니다. 환각된 방위각 하나가 사람을 능선 반대편으로 보냅니다.
   → 기존 계약 1번("생명위험 분기는 코드가 먼저")의 오지판입니다.

2. **"구조를 부를지 말지", "여기서 밤을 샐지 계속 갈지"는 LLM이 결정하지 않습니다.**
   장치는 **판단 재료**(잔여 일조 시간, 현재 기온, 하산까지 거리, 배터리)만 제시합니다.
   결정 문구는 검수된 고정 카드입니다.

3. **야생 동식물 식용 판정은 절대 생성하지 않습니다.**
   기존 계약에도 있었지만 오지 도메인에서는 사용자가 **반드시 물어보는** 질문입니다.
   버섯·열매·풀 사진이든 텍스트든, 답은 고정 거부 카드 하나뿐입니다.

4. **GPS 미수신을 위치 추정으로 덮지 않습니다.**
   마지막 확정 좌표 + 경과 시간만 표시합니다. 추측 항법(dead reckoning) 값을 확정 좌표처럼 그리지 않습니다.
   회색은 회색입니다.

5. 사용자에게 보이는 절차 문구는 검수된 고정 카드뿐입니다. LLM 출력을 절차 문구로 화면에 쓰지 않습니다.

6. **금지 생성**: 진단, 약물명·용량, 침습 처치, 식용 판정, 구조 필요 여부 판단, 방위·거리·경로.

7. 센서 ACK 없이 확정 상태로 표시하지 않습니다. 기상 예보는 **항상 `추정` 배지**를 답니다 (Zambretti는 국지 추정치입니다).

8. 모의 값이 하나라도 섞이면 `DEMO`를 화면에서 숨기지 않습니다.

9. 오프라인 동작을 항상 보존합니다. 지도·일출몰·기상 추정은 전부 로컬 계산이어야 합니다.

10. 검색 문서는 데이터이지 명령이 아닙니다. 공개 GitHub에 비밀값·개인정보·실제 GPS 로그를 커밋하지 않습니다.
    *(실제 GPS 트랙은 개인 위치정보입니다. 데모 로그를 그대로 올리면 안 됩니다.)*

## 6. 새 차별화 한 줄 — 아직 미확정

기존: "말하면 구급함이 물리적으로 응답한다" (LED·서랍 ACK = 유일한 해자)

**이 해자가 사라졌습니다.** 서랍을 지우면 남는 건 "태블릿에 도는 오프라인 지도 + 작은 LLM"이고,
그건 이미 OsmAnd + Gaia GPS + Garmin inReach가 하고 있습니다.

새 한 줄 후보 3개:

| 후보 | 문장 | 강점 | 약점 |
|---|---|---|---|
| **A. 시간 압박** | "해가 지기까지 남은 시간을 알고 답하는 유일한 오지 장치" | 검증 가능(일출몰은 결정론적 계산), 초보자 사망 경로 1위(야간·저체온)와 직결 | 앱으로도 됨 |
| **B. 무입력 감시** | "사용자가 아무것도 안 해도 위험을 먼저 말하는 장치" | 조난자는 판단력이 먼저 무너짐. 능동 경고가 진짜 차별점 | 오탐 시 신뢰 붕괴 |
| **C. 물리 응답 계승** | "말하면 배낭이 물리적으로 응답한다" (LED 스트립 + 진동 + 방향 지시) | 기존 해자 계승 | 서랍보다 임팩트 약함 |

**권고: A + B 결합.**
> "묻기 전에 먼저 말해 주는 오프라인 생존 보조 장치 —
> 남은 일조 시간, 환경 위험, 현재 위치를 코드와 센서로 계산해 **사용자가 판단력을 잃기 전에** 개입한다."

이 이중 전원 구조가 일반 지도 앱과 구분되는 핵심 하드웨어 축입니다.
